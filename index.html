核心能力

三个平级动作，
决定“键鼠现在归谁”

连接（建链）、键鼠共享（跨屏用）、远程控制（接管）是三个互不隶属的平级动作。 连接可以一直挂着，共享与远程控制只决定键鼠的归属。

键鼠共享

把设备摆成二维网格，拼成任意形状的虚拟大屏。鼠标撞到边缘就走到相邻设备，可以连续走完整张大屏。

  • 任意时刻只有一台显示光标，其余待命
  • 撞边自动跨屏开关，位置可拖拽调整
  • 实时画出设备间的方位箭头
  • 被控端本地键鼠完全锁死，不会互相抢

远程控制

勾选一台专注操作，或勾“全部”多台同步接管。两阶段授权：对方点下“允许”之前，不会接管本机。

  • 被控端本地键鼠完全锁死
  • 鼠标锁在对方屏幕内，不撞边退出
  • 被控端可随时单方面结束

剪贴板三合一

文字、图片、文件三路同步，还能跨屏直接 Ctrl+C / Ctrl+V。拖动一个文件到隔壁屏幕，落点直接就位。

  • 只在光标位于对端时接管，本机操作不受影响
  • 文字 / 图片跨屏 Ctrl+C·V，端到端验收通过
  • 4.7 新增贴边感应带，文件直接甩到对面屏幕
  • 单批上限、接收目录、进度条

三平台 · 免 GUI 模式

Windows、Linux（X11）、macOS（CoreGraphics）各有独立注入后端。 还有一套纯标准库 HTTP+SSE 的浏览器控制端，下载到开发板就能用，不需要装图形界面。

  • Windows SendInput / Linux XTest / macOS CGEvent
  • 非 Windows 上 import 不再崩
  • 免 GUI 版：8.1MB，可开机自启

防套娃 / 单主控保护

三条硬约束，保证你的局域网不会串成一串。

不能反向控制本机正被别人控制时，无法再连接或控制其他电脑。
拒绝被套娃本机正在控制别人时，拒绝第三方向本机发起控制。
唯一主控同一时刻只允许一个控制端抓住本机，第二个被明确拒绝并写日志。

4.7 更新

改名 BridgeLink，
贴边拖拽文件

4.7 把项目从 LanKVM 正式更名为 BridgeLink，包目录、可执行文件、 配置目录、接收目录、环境变量全部改完；同时新增 贴边感应带——从资源管理器按住文件往屏幕边缘一拖， 就能直接甩到对面电脑上（仿「无界」的 OLE 方式）。

01

全量改名，旧版仍可互联

Python 包目录 lankvm/ → bridgelink/， 可执行文件、配置目录 %APPDATA%\BridgeLink\、 接收目录、环境变量 BRIDGELINK_CONFIG 全部换新。 网络协议帧格式、端口、握手流程完全不变，新旧版本之间照样能互联。

包目录改名协议不变新旧互联
02

贴边感应带，文件真能甩过去

上一版靠读剪贴板快照拿载荷，但资源管理器拖文件时 CF_HDROP 只存在于拖动源的 OLE 数据对象里， 剪贴板里根本没东西——所以那条路从未真正跑通过。 4.7 改用系统 OLE 放置目标接住拖拽，这才是唯一可靠的载荷来源。

OLE 放置目标CF_HDROP保留目录结构
03

感应带平时完全不创建

常驻会挡住屏幕最边缘几个像素的点击。现在只在左键按住且拖动超过 8 像素 时临时铺一条 4 像素透明带，alpha=1 肉眼不可见但仍参与命中测试， WM_NCHITTEST 返回 HTTRANSPARENT 让普通点击照旧穿透。 拿到文件立刻给拖动源发 Esc，避免资源管理器把文件就地复制。

按需创建8px 阈值即时拆带
04

双路径并存，互不冲突

v4.6 的剪贴板路径负责文字/图片，v4.7 的感应带路径负责文件/文件夹。 感应带接管后会抑制剪贴板路径（_band_owned 标记）， 否则同一批文件会被发两遍，对端收到 xxx(1).txt。 接收端不覆盖用户剪贴板，批次号带 band: 前缀区分。

剪贴板路径感应带路径批次去重
05

Windows exe 正式交付

交付包现在直接带 exe：BridgeLink.exe（22.7MB，无控制台，双击即用） 与 BridgeLink-headless.exe（8.1MB，带控制台，适合开发板 / 开机自启 / 看日志）。 顺手修掉打包版双击一闪就没的问题——Windows 控制台编码导致的 UnicodeEncodeError。

主程序 exe免 GUI 版启动不闪退

30 秒上手

两台机器，
三步接通

  1. 01

    两台机器各跑一份 BridgeLink

    解压即用，无需安装、无需依赖。Windows 10 / 11 均可运行。

  2. 02

    两边都点顶栏「启动监听」

    默认端口 8899。首次运行请允许防火墙放行 UDP 8898 / TCP 8899。

  3. 03

    添加设备 → 连接 → 推到屏幕边缘

    在「设备」页填对方的局域网 IP，点连接。到「键鼠共享」页把对方摆到本机右边， 然后把鼠标推到屏幕最右边——键鼠就过去了。

命令行 
BridgeLink.exe --peer 192.168.1.23@right --peer 192.168.1.24@left
BridgeLink.exe --peers "192.168.1.23@right,192.168.1.24@up" --name 考场机A
BridgeLink.exe --port 8899 --max-peers 0        # 监听端口；0 = 设备数不限
BridgeLink.exe --tray                        # 启动即最小化到托盘
BridgeLink.exe --headless --web-port 8890     # 免 GUI 模式，浏览器打开 http://本机IP:8890/
BridgeLink.exe --selftest 12                 # 自检 12 秒并写报告到 %TEMP%
常见问题

排查与限制

扫不到设备怎么办？

确认两台机器在同一网段、对方已点「启动监听」，并放行防火墙 UDP 8898 / TCP 8899；也可以用设备页的「深度扫描」逐个 IP 尝试。

连上了但键鼠不动？

两边都用管理员身份运行（Windows 的 UIPI 会拦截跨权限注入），并确认设备列表里的「启用」是勾上的。

撞边没反应？

检查「键鼠共享」页的「撞边自动跨屏」是否勾选，以及该方位是否有一台已连接的设备——只有待命设备不会响应撞边。

远程控制动不了？

对方可能正停在「控制请求」弹窗等你点允许；也可能本机正被别的设备控制。顶栏横幅会写明当前状态。

想退出却被对方按住？

被控端在「远程控制」页点「结束本机被控」即可单方面收回键鼠，控制端会同步结束。

有哪些已知限制？

无法拦截 Ctrl+Alt+Del 等 Windows 安全序列；普通权限无法向管理员窗口注入；一台被控端同时只受一个控制端控制；明文 TCP 仅限可信局域网；UDP 发现不跨网段；边缘按整个虚拟桌面最外侧判定。
